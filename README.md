## What changed on Oct 2

- **One sign-in list with access levels.** `allowed/{emailKey}/tier` is `admin`, `crew`, or `walker`. Admin opens Projects and the CRM. Crew is sent to `my.html`. Walker is sent to `routes.html`. The Projects page Team tab sets the level. When Russel signs in, any entry with no level gets `admin` (one time; the three entries on Oct 2 were Russel, Ethan, and 2018dhd@gmail.com, all confirmed admin).
- **Rules** (`database.rules.combined.json`, generated by `dev/gen_rules.py`, tested by `dev/rules.test.mjs` in the Firebase emulator: 56 checks pass). Every path checks the tier, only admins can change the list, every check requires a verified Google email (closes the hole where a future email/password account could claim an allowlisted address), a signed contract cannot be edited or deleted (only its void fields), crew can only mark their own crew's jobs and enter their own unapproved hours, walkers read only their own day reports. Includes the paths for the Employee View, Employee Manager, and Claude's own sign-in (`integrations/{uid}`).
- **CRM 1.1:** phone key in E.164 form on every client plus `phoneIndex`, duplicate warning as you type (quick add and client dialog), CSV import skips a matching phone. Contracts: three SAMPLE templates load into an empty Contracts list (Fall Cleanup, Seasonal Snow, Christmas Lights); a template is assigned by service type; the signing screen is full screen on the iPad with boxes, initials, finger or Pencil signature, the admin's stored countersignature, payment at signing, Sign and lock (SHA-256 fingerprint, witness, device, time), print or save PDF, email link, and void with a reason. Sample contracts require a "this is a test" tick and never queue QuickBooks work. QuickBooks queue (`sync/qb`): customer rows (search before create), and per signing either match-payment (GoPayment card at signing, no invoice), record-payment, or invoice. Copy the queue for Claude, paste the results back to write the QuickBooks id onto the client. Payment methods now lead with "Card (QuickBooks GoPayment)". Fixed: payment method dropdown showed blank labels (bug in the Oct 1 build).
- **Routes:** walkers come from the team list (old `walkers` list still read during the switch), admin is anyone with tier admin, a walker's report is also written to `routeLogsByWalker/{key}/{date}` so he can see his own history and nobody else's.

## Deploy order (Russel)

The order matters. The old Projects page cannot sign Russel in under the new rules (its sign-in step writes his entry without an access level, which the new rules refuse), so the new Projects page goes up first and runs once on the old rules.

1. Turn on 2-Step Verification on the Google account (the Firebase console said it is required from Oct 2).
2. Projects page > More > Tools > Backup: download one before changing anything.
3. GitHub website, repo `mb-projects`: Add file > Upload files > `index.html` only > Commit. Wait two minutes.
4. Open the Projects page, hard refresh, sign in as Russel. This gives the three existing entries the admin level while the old rules are still in place. Check More > Team: all three show Admin.
5. Firebase console > Realtime Database > Rules: select all, paste `database.rules.combined.json`, Publish.
6. Hard refresh the Projects page and confirm projects and tasks still load.
7. Upload `crm.html`, `routes.html`, `routes-seed.json`. Do not push from the old local clone (it shows index.html as deleted).
8. iPad rehearsal, master plan section 5.8.

## Working rule for future sessions

1. Start by downloading the live page (`curl https://apps.mangbrothers.com/<page>`) and compare it to the copy here. If they differ, the live page wins and gets written here first.
2. Edit the source, build a preview, test it in headless Chromium, show Russel the preview.
3. When he approves, write the new page (and rules if they changed) back to this folder with `project_write` before handing him the download.
4. Update the master plan with what changed.
